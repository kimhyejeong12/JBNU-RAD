# Tailwind 전환 설계 (리디자인 1단계)

화면 스타일을 지금 CSS에서 Tailwind CSS로 바꾸는 작업의 설계. 끝나면 지우는 문서.

## 왜

- 다음에 화면 전체 디자인을 바꿀 예정임 (리디자인 2단계). 그 전에 스타일을 고치기 쉬운 바탕을 업계에서 많이 쓰는 조합으로 맞춰 둠
- 지금 CSS의 약점
  - 18개 파일 469줄, 불러오는 순서가 곧 우선순위 (`responsive.css`가 마지막이어야 함)
  - 클래스 163종이 전역이라 어느 화면에 쓰이는지 검색해야 앎
  - 색 35종 · px 값 63종이 파일마다 흩어져 있음
- 리디자인은 두 단계로 나눔 (사용자 결정)
  - **1단계 (이 문서)**: 스타일 기반 교체. 화면은 그대로
  - **2단계**: 배치 · 색 · 컴포넌트를 새로 정함. 이 문서 범위 밖

## 목표

- 모든 화면 스타일을 Tailwind v4 유틸리티 클래스로 표현함. 옛 CSS 파일 18개를 지우고 진입 CSS 하나만 남김
- 색 · 글꼴 · 반응형 기준을 진입 CSS의 `@theme`에 이름 붙인 토큰으로 둠
- shadcn/ui를 쓸 바탕을 깔아 둠: `components.json`, className을 합치는 `cn()` 도우미, shadcn 이름 규칙의 색 변수(`--background` · `--primary` 등)를 지금 색에 연결
- CSS 클래스 이름에 기대던 코드를 `data-` 속성 등으로 바꿈

## 비목표

- 디자인 변경 — 배치 · 색 · 간격 · 글꼴 · 아이콘은 2단계
- 값 정리 — 12.5px 같은 값을 Tailwind 단위로 맞추는 일은 2단계
- shadcn/ui 부품 도입 · lucide 아이콘 · 라우터 · 새 기능
- 서버 코드(`sentinelai/`) · API · `docs/` 변경

## 실패로 보는 것

- **화면이 달라짐** (가장 중요, 사용자 강조). 색 · 간격 · 글꼴 · 줄바꿈 · 반응형(760px · 1150px) · hover · 포커스 · 툴팁 · 서랍 · 모달 · 전환 효과 모두 포함
- 기능 동작이 달라짐 — 단위 시험 · 화면 글자 비교로 잡음
- 외부 요청이 생김 (CDN · 웹폰트)
- className이 너무 길어 읽기 어려워짐 — 여러 곳에서 되풀이되는 모양은 컴포넌트나 상수로 묶음

## 제약

- 외부망 없음 — Tailwind는 빌드 때만 씀. 결과는 지금처럼 `sentinelai/web/static/`에 커밋 (`make front-build`, `make front-check` 통과)
- 버전: `tailwindcss` · `@tailwindcss/vite` 4.3.x (Vite 8 지원 확인 — peer `^5.2.0 || ^6 || ^7 || ^8`), `clsx` 2.x, `tailwind-merge` 3.x. shadcn CLI는 4.x (쓸 경우)
- 설정 파일(`tailwind.config.js`) 없이 CSS 안의 `@theme`으로 설정 (v4 방식)
- 지원 브라우저: Chrome · Edge 111+, Safari 16.4+, Firefox 128+ (Tailwind v4 요구). Chrome · Edge · Safari는 지금 Vite 8 빌드 대상과 같고 Firefox만 114 → 128로 올라감. 이보다 오래된 브라우저에서는 cascade layer를 몰라 스타일이 통째로 빠지고 `build.target`으로 낮출 수 없음
- 프로젝트 규칙: `CLAUDE.md` §4 (하나씩 바꾸고 확인, 커밋 형식), `FRONTEND_GUIDE.md` §9 (폴더 · 파일 기준, 기능 폴더끼리 import 안 함)
- 브랜치 `redesign`(지금 `main` `69c4cd3`에서 만듦)에서 작업하고 PR로 `main`에 병합

## 확인 기준

- **스크린샷 비교** (완료 조건)
  - 대상: 세 역할(`dev-root` · `dev-op` · `dev-user`) × 1440px · 390px × 화면 상태
  - 화면 상태: 메뉴 · 탭마다, 패널을 연 상태, 좁은 화면의 서랍, 툴팁, 기준 문서 창, 빈 목록, 로그인 · 비밀번호 변경 화면, hover · 포커스가 있는 주요 요소
  - 같은 서버 · 같은 데이터에서 전환 전 번들(`main` `69c4cd3`의 `static/`)과 전환 후 번들을 번갈아 띄워 찍음. 자동 작업이 데이터를 바꾸면 비교가 흔들리므로 끄거나, 바뀌는 글자(시각 등)는 가림
  - 차이 0이 목표. 글꼴 안티앨리어싱 정도만 허용. 남는 차이는 원인을 찾아 고치고, 못 고치면 사용자에게 보여 주고 결정을 받음
- 단위 시험(지금 95개) · 타입 검사 · 린트 통과
- 화면 글자 비교 (지금까지 쓴 Playwright 흐름 8개) — 전후 같음
  - 지금 흐름은 CSS 클래스(`.row` · `.nav[data-view]` 등)로 요소를 찾아 전환하면 깨짐. CSS를 건드리기 전에 id · 역할 · 글자 · `data-` 속성으로 찾게 고치고, 옛 번들에서 기준 결과를 먼저 기록함
  - 흐름이 `className`을 출력하는 부분은 비교에서 뺌 (클래스는 일부러 바뀜)
- `make front-check` 통과, Network에 다른 출처 요청 없음

## 빌더에게 맡기는 것

- 토큰 이름 (색 · 글자 크기 · 반응형 기준), shadcn 색 변수와 지금 색의 연결
- 옛 CSS와 Tailwind가 함께 있는 동안의 우선순위 처리 (예: 옛 CSS를 낮은 cascade layer에 넣기)
- Tailwind 기본 스타일 초기화(preflight)로 달라지는 기본값을 지금 값으로 되돌리는 방법
- 복잡한 선택자 옮기기 — 위치로 칸을 숨기는 `.tr > :nth-child(n)`, 숨은 형제에 기대는 `.run + .run` 여백, 등급 이름으로 만드는 클래스 등
- 반응형: 지금은 큰 화면 기준 `max-width` 쿼리. Tailwind의 `max-*` 변형을 쓸지, 작은 화면 기준으로 뒤집을지
- 영역을 옮기는 순서, 커밋 단위
- 스크린샷 비교 도구 (지금 `shot.mjs` 계열 Playwright 스크립트를 넓히거나 새로)
- shadcn 바탕을 CLI(`shadcn init`)로 깔지 손으로 쓸지
